## 4. 시험하지 못한 것과 그 이유

### 4.1 로그인이 필요한 시험

- 구글 로그인, 로그아웃, 로그인 후 화면과 API 전부. 이유: 구글 로그인은 이번 시험의 금지 조건임. 대체: 코드 읽기, `npm test`, `lib/ai` 직접 호출. 해당 판정: F1-2, F1-3, F2-3, F2-5, F3-2, F4-4, F5-4, 지난 기록 3초
- 로그인 상태 API의 오류 응답(빈 일기, 501자, 잘못된 UUID, 다른 사용자의 ID)의 HTTP 시험. 이유: 라우트가 로그인 확인을 먼저 함. 대체: `normalizeContent` 단위 시험과 라우트 코드 읽기
- 사용자 ID가 로그인마다 같은지 실제 2회 로그인 시험. 대체: Auth.js 소스 판독

### 4.2 모델 호출 제약

- 모델 2개가 모두 실제로 실패하는 상황. 이유: 호출 예산 4회 사용(상한 5회)이라 둘째 모델의 실패를 주입하지 않음. 대체: 시간 제한 1ms와 키 없음으로 `pending` 반환을 확인하고, 첫 모델의 실제 시간 초과 1회를 확인함
- PRD 4.5절의 위기 예문 5개와 일반 예문 5개 판정. 이유: 호출 예산. 대체: 목록 시험 29건(호출 없음)과 모델 판정 2건
- 공감 메시지의 금지 규칙 표본 확대. 3건만 확인함
- 프롬프트 태그 경계 이탈(2.10절)은 실행하지 않음. 이유: 호출 예산

### 4.3 빌드, 환경, 브라우저

- `npm run build` 미실행. 이유: 실행 중인 개발 서버가 같은 `.next` 폴더를 쓰므로 덮어쓸 위험이 있음. 개발 서버는 끄지 말라는 지시에 따름. 별도 빌드 확인이 필요함
- 375px 모바일과 데스크톱 레이아웃, 키보드 조작, 글자 대비: 브라우저 시험을 하지 않음
- 동시 요청 경합(저장 버튼 연타, 다시 분석 연타): 코드 읽기만 함
- 보안 헤더와 배포 환경 설정: 로컬 응답만 확인함
